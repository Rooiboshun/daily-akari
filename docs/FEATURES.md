# 機能台帳

このリポジトリに実装されている機能を1枚で見るための台帳。
機能を足した・挙動を変えた・機能を消したときは、同じコミットでここを更新する。

最終更新: 2026-09-13

---

## 状態

盤面ロジック + 遊べる UI。HTML/CSS/JS だけで動き、ビルドも依存パッケージも無い
（`index.html` を GitHub Pages に置けばそのまま公開できる）。

## 盤面ロジック (`src/akari.js`)

依存ライブラリなしの ES モジュール。ブラウザからも Node からもそのまま読める。

### 盤面の表現

| 機能 | 関数 | 説明 |
| --- | --- | --- |
| テキストから読む | `parse(text)` | `.` 白 / `#` 数字なしの黒 / `0`-`4` 数字つきの黒 |
| テキストに書く | `render(puzzle, state?)` | `state` を渡すと照明を `L` で描く |
| 索引の事前計算 | `buildIndex(puzzle)` | 白マス一覧・各マスから見える範囲・数字マスと隣接白マスを先に作る。黒マスの配置にだけ依存するので、数字を削りながら何度も解く場面で使い回せる |

### ソルバ

| 機能 | 関数 | 説明 |
| --- | --- | --- |
| 制約伝播 | `propagate(ix, st)` | 分岐せずに決まるところだけ埋める。矛盾を見つけたら `false`。三つの規則（照らし合い禁止 / 数字一致 / 全白マス照明）を変化が止まるまで回す |
| 解の数え上げ | `solve(ix, limit)` | 制約伝播＋バックトラック。解を `limit` 個まで返す。一意性の検査は `limit=2` で `count===1` を見る |
| 妥当性の検査 | `isValidSolution(ix, st)` | 完成した配置がルールを満たすか |
| 論理だけで解けるか | `solvableByLogicAlone(ix)` | 分岐なし（制約伝播だけ）で解けるかを調べる。難易度の目安 |

`solve` の戻り値には `guesses`（分岐した回数）と `logicOnly`（一度も分岐せずに解けたか）が入る。

### 盤面生成

| 機能 | 関数 | 説明 |
| --- | --- | --- |
| 一意解の問題を作る | `generate(opt)` | 削り出し方式。①黒マスを 180 度回転対称に配置 → ②全白マスを照らす配置をランダムに作る → ③全黒マスに数字を入れる → ④数字を1つずつ外し、ソルバで一意のままか検査 |
| 乱数の種 | `seedFrom(str)` | 文字列から 32bit の種（FNV-1a） |
| 疑似乱数 | `makeRng(seed)` | mulberry32。同じ種なら必ず同じ列 |

`generate` のオプション: `w` `h` `blackRatio` `rng` `logicOnly` `attempts`。
`logicOnly: true` を指定すると「分岐なしで解ける」問題だけを作る。

数字の削り出しは1周で済む。数字を外すと解は増えこそすれ減らないので、
一度外せなかった数字は後からも外せないため。結果は
「どの数字を1つ外しても一意でなくなる」極小の問題になる。

### 日替わり

| 機能 | 関数 | 説明 |
| --- | --- | --- |
| 難易度の設定 | `DIFFICULTIES` | `easy` 7x7 / `normal` 9x9 / `hard` 10x10。`hard` だけ試行錯誤を許す |
| その日の問題 | `dailyPuzzle(dateStr, difficulty)` | 日付を乱数の種にするので生成が決定的。サーバも DB も要らず、GitHub Pages のままで「毎日同じ問題が全員に出る」が成立する |
| 今日の日付 | `todayString(date?)` | ローカル時刻を `YYYY-MM-DD` で返す |

## プレイ UI (`index.html` / `src/ui.js` / `src/style.css`)

盤面のルールは `akari.js` が全部持っていて、`ui.js` は「描く・触る・数える・
覚えておく」だけを担当する。フレームワークもビルドも使っていない。

### 遊ぶ

| 機能 | 操作 | 説明 |
| --- | --- | --- |
| 照明を置く/外す | 白マスをクリック | キーボードの Enter / Space も同じ |
| 「置かない」印 | 右クリック / 長押し / `x` キー | スマホ用に「タップ: 照明⇄×印」ボタンでも切り替えられる |
| マスの移動 | 矢印キー | 黒マスは飛び越える |
| 点灯の表示 | 自動 | 照らされている白マスが明るくなる |
| 照らし合いの警告 | 自動 | ぶつかり合っている照明を赤くする |
| 数字の達成 | 自動 | 本数が合った数字は緑、多すぎる数字は赤 |
| クリア判定 | 自動 | 4つのルールを全部満たした瞬間に時間とヒント数を出す |

### 助け

| 機能 | ボタン | 説明 |
| --- | --- | --- |
| まちがい探し | `まちがい探し` | 答えに無い照明を赤枠にする。解が一意なので「答えに無い照明＝間違い」と断定できる |
| ヒント | `ヒント` | 間違った照明があれば1つ外す。無ければ正しい照明を1つ置いて印を付ける |
| やり直す | `やり直す` | 盤面と時間とヒント数を戻す |
| 答えを見る | `答えを見る` | 確認のうえ答えを表示（記録は残らない） |

### 日付とアーカイブ

| 機能 | 説明 |
| --- | --- |
| 日付の移動 | `◀ ▶`・日付入力・`今日`。未来の日付は選べない（今日が上限） |
| 難易度の切り替え | やさしい 7×7 / ふつう 9×9 / むずかしい 10×10 |
| URL | `#2026-09-13/normal` の形。そのまま貼れば同じ問題が開く |
| 途中経過の保存 | `localStorage` に日付・難易度ごとに保存（盤面・経過時間・ヒント数・クリア済みか） |
| 時間の計測 | 最初に触った時から計測。タブを裏に回している間は止まる |

生成は問題を開くたびにブラウザの中で走る（1問あたり数ミリ秒）。
サーバも DB も無いので、過去のどの日付でも同じ問題がその場で再現される。

## 道具 (`tools/`)

| 機能 | コマンド | 説明 |
| --- | --- | --- |
| 検証 | `npm run verify` | ソルバと生成器の検証（下記） |
| UI の検証 | `npm run uitest` | ヘッドレス Chrome で本物の画面を操作して検証（下記） |
| 手元で遊ぶ | `npm run serve` | 依存なしの静的サーバ。ES モジュールは `file://` では読めないので手元ではこれを挟む |
| 問題を覗く | `npm run peek -- 2026-09-20 hard -a` | 指定した日付・難易度の問題（と答え）を表示 |

### 検証の内容 (`tools/verify.mjs`)

- **A. ソルバの基本動作** — 答えが手で確かめられる小さな盤面で、解の数まで含めて照合
- **A2. 総当たりとの突き合わせ** — ランダムな 4x4 盤面 60 個について、全白マスの部分集合を
  全部試す愚直な数え上げと `solve` の答えが一致するか。伝播と分岐が解を落としたり
  二重に数えたりしていないことの裏取り
- **B/C/D. 生成した盤面** — 各難易度 12 問について、盤面テキストから読み直して
  生成器とは独立に解き、①解が一意 ②解がルールを満たす ③生成時の解と一致
  ④数字が極小（どれか1つ外すと条件が崩れる）を検査
- **E. 日替わりの決定性** — 同じ日付なら同じ問題、違う日付なら違う問題、
  同じ日でも難易度が違えば違う問題

### UI の検証の内容 (`tools/uitest.mjs` + `tools/selftest.html`)

追加の依存パッケージは入れていない。`tools/selftest.html` が本物の
`index.html` の中身を取り込んで `src/ui.js` を読み込み、実際の click /
contextmenu を投げて自己採点し、`tools/uitest.mjs` がヘッドレス Chrome
（`--dump-dom`）でそのページを開いて結果を読む。22 項目。

盤面が問題どおり描けるか / 右クリックの×印 / 照らし合いの赤表示 / 照明数の表示 /
途中経過の保存と復元 / やり直す / まちがい探し / ヒント2種 / 答えどおり置いたときの
クリア判定 / 日付の移動と URL / 手つかずの盤面を間違い扱いしないこと。

Chrome の場所は環境変数 `CHROME` で指定できる。ブラウザが無い環境では
終了コード 2 で「見つからない」と言って止まる。
